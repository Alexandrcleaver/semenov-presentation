# Инструкции для Codex / ИИ-редактора

## Основной контракт
Итоговая презентация — **один полностью автономный HTML**: `dist/presentation.html`.
Редактируются только исходники внутри `src/`.

## Уменьшение токенов
- НЕ читай `dist/presentation.html` целиком: там Base64-медиа (~17 МБ).
- НЕ выводи в контекст `src/assets/*`.
- Начни с `npm run locate -- N` и `src/deck_order.json`, чтобы найти нужный слайд и прямые зависимости CSS/JS.
- Открой только нужный `src/slides/NN-*.html`.
- Для точечной CSS-правки используй `src/styles.json` и поиск селектора по CSS-файлам;
  не загружай все 42 файла в контекст целиком.
- JS-навигация: `src/scripts/01-main-player.js` — общий контроллер, не менять без явного запроса.
- Большие общие изменения требуют визуальной регрессионной проверки всех слайдов.
- Все изменения в структурных исходниках, не в собранном HTML и не в asset manifest.

## Инварианты
- Сохранить 1920x1080 базовый холст и навигационный порядок `src/deck_order.json` (он не полностью совпадает с порядком HTML в `src/slides.json`).
- Сохранить работу Enter/Space/ArrowRight, навигацию назад, галерею, ссылки и `postMessage`.
- Сохранить все встроенные изображения, анимированные WebM/MP4, шрифты.
- Сохранить последовательность CSS, пока не доказана регрессионная эквивалентность.
- Не убирать исторические CSS-исправления только потому, что они выглядят лишними.
- Не вводить внешние CDN: HTML должен запускаться локально без сети.

## Процесс
1. Определи номера слайдов, которых касается правка.
2. Найди относящиеся к ним исходники; сначала изолированная правка.
3. Выполни `npm run build`.
4. Проверь слайд, его соседей, переходы вперёд/назад и повторный вход.
5. Обнови `docs/PROJECT_STATE.md`, `docs/CHANGELOG.md`.
6. Выдай именно `dist/presentation.html`, а исходники сохрани в проекте.

## Рефакторинг
В первой версии разбиение lossless: стили ещё не сгруппированы по слайдам, JS остался
связным. Не выдавай первый этап за завершённую архитектурную переработку.

## Точечные правки слайдов — обязательный маршрут
1. Сначала `npm run locate -- N` (номер в порядке показа, не номер HTML-файла).
2. Прочитай HTML указанного слайда и только нужные диапазоны CSS/JS из отчёта. Для деталей используй раздел этого слайда в `docs/SLIDE_MAP.md`, затем точечный поиск селектора/функции.
3. CSS-результаты — статические кандидаты. Проверяй селектор, условия, `!important` и последующие переопределения через `docs/CSS_MAP.md`; для анимаций — `docs/ANIMATION_MAP.md`. Отсутствие связи означает «не установлена», а не отсутствие зависимости.
4. Читай необходимые общие зависимости по функциям и диапазонам строк. Не открывай весь движок для текстовой/CSS-правки. Слайд 3 использует слайд 2; слайд 9 связан с предзагрузкой из слайда 8; iframe слайда 10 имеют отдельный контекст.
5. Не загружай собранный HTML и Base64 в контекст. Бинарные ассеты проверяй по manifest/хешу; открывай визуально только когда задача касается изображения или видео.
6. Не изменяй другие слайды без конкретной подтверждённой причины. Изменение общего класса/контроллера требует перечисления затронутых слайдов и соответствующей регрессии.
7. После правки: `npm run build`, проверка целевого слайда, соседей, вперёд/назад и повторного входа; для медиа — play/pause, для внутренних этапов — шаги и галерея. Общие изменения требуют проверки всех затронутых слайдов.
8. При изменении исходников/зависимостей обнови индексы: `npm run maps`; документацию состояния и changelog. Генератор и locate не читают dist или бинарные ассеты.
9. Для изменений только инструментов/документации обязателен `npm run verify:reference`: HTML должен остаться побайтно эталонным. После намеренной правки презентации несовпадение эталонного хеша ожидаемо и не заменяет регрессию.

Инструменты разработки редактируются в `scripts/`, документация в `docs/`; правило «только src» относится к коду и содержимому самой презентации. Индексы не являются новым движком: итог по-прежнему один автономный `dist/presentation.html`.

## Автоматический выбор браузерной регрессии
- После изменения HTML конкретного слайда: locate → build → `npm run regression:quick -- --slide=N`. Для layout/анимаций/медиа/переходов дополнительно `npm run regression:full -- --slide=N`.
- Для CSS/JS/ассета передай каждый изменённый путь: `--changed=src/styles/FILE.css`, `--changed=src/scripts/FILE.js`, `--changed=src/assets/FILE`. Не ограничивай общую CSS-правку только одним номером. Неизвестные и глобальные зависимости требуют проверки всех 39 слайдов.
- Общий контроллер, shell, порядок, шрифты, glow и presenter UI: полный общий прогон. Команды и ограничения — docs/REGRESSION_PLAN.md.
- Работай с JSON-отчётом и только относящимися к задаче PNG/diff; не загружай все карты/скриншоты в контекст для мелкой правки.
- Скриншоты-кандидаты и отсутствие ошибки JS не доказывают визуальную корректность. Просмотри нужные кадры. Не обновляй baseline при отличии автоматически; отличающийся baseline заменяется только после отдельного разрешения пользователя и явного просмотра.
- Отдельно сообщай pass/fail/pending и известные проблемы. Не скрывай исторический stage9 или визуальные дефекты слайдов 11/12/31. Источники презентации в текущем этапе не менять.
- Сохраняй параметры браузера/времени/окна. Для работы над инструментами сохраняй эталонный SHA-256 и выполняй verify:reference; документацию результатов обновляй по фактически завершённым прогонам.
