# План браузерной регрессии

## Контракт и запуск
Тесты собирают проект и открывают только `dist/presentation.html` через `file://`. src/HTML/CSS/JS, медиа и движок не изменяются. Контроль текущего этапа: SHA-256 `d3e1a606a834beca8a4c6a172b4f71049324be8647ed406e5e4a8111a726c648`.

```powershell
npm run regression:quick
npm run regression:full
npm run locate -- 30
npm run regression:quick -- --slide=30
npm run regression:full -- --slide=30
# Общая CSS-правка: включить все подтверждённые зависимости и соседей
npm run regression:full -- --slide=30 --changed=src/styles/40-storytelling-fix-tools-grid.css
# Глобальный контроллер/эффекты: автоматически вся презентация
npm run regression:full -- --changed=src/scripts/01-main-player.js
npm run test:regression-tools
```

Аргументы `--changed=` можно повторять. `--slide=N` без changed предназначен для HTML-правки: сам слайд, подтверждённые пары 2/3, 8/9, 9/10 и соседние переходы. Для CSS/JS обязательно передать изменённые пути. CSS-файл анализируется консервативно целиком, не как доказанно изолированный селектор. Общие файлы и неизвестные связи включают все 39 слайдов. Статический индекс не доказывает отсутствие динамической связи; сомнение требует полной проверки. locate выводит выбранные номера и команды.

Проверка эталонного SHA включена в обоих уровнях. После будущей разрешённой правки презентации хеш закономерно изменится: потребуется отдельно пересмотреть контракт хеша, не переписывая reference.json для сокрытия отличий. В этом этапе несовпадение всегда ошибка.

## Существующие инструменты
Используются уже установленные Playwright, pngjs и pixelmatch из комплекта Codex. Для обзорных листов — установленный там же sharp. package.json не содержит новых зависимостей, npm install и загрузка браузера не выполняются.

`runtime.mjs` сначала ищет пакеты проекта, затем `$env:REGRESSION_MODULES`, затем комплект в `%USERPROFILE%/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules`. Для другой машины задайте путь к уже установленному комплекту; при отсутствии тест завершится с объяснением. Браузер: установленный Chrome, по умолчанию `C:/Program Files/Google/Chrome/Application/chrome.exe`; переопределение `$env:REGRESSION_BROWSER`. Браузерная версия входит в manifest эталонов. Переход на другую версию не разрешает автоматически обновить эталоны.

## Воспроизводимость
- Headless Chrome; окно/viewport 1920×1080, DPR=1, ru-RU, Europe/Moscow, dark, prefers-reduced-motion=no-preference, offline=true.
- Playwright clock: 2026-10-13T09:00:00Z, сразу pauseAt +1000 мс; далее время движется только командами clock. Math.random воспроизводимо инициализирован seed=1729 в родителе и iframe.
- Быстрый уровень использует fastForward для освобождения таймеров. Полный — runFor для набора текста, Solitaire и сценариев iframe; конкретные интервалы находятся в run.mjs. CSS-анимации не считаются автоматически проверенными по виртуальному времени JS.
- Для контрольных кадров CSS/WAAPI фиксируются: settled = конечное состояние, mid = 350 мс; SVG SMIL = 0; видео = 0,5 с (или половина длительности короткого видео). Перед снимком ожидается готовность/seek. Для settled дополнительно screenshot animations=disabled; mid сохраняет замороженное промежуточное состояние.
- Фиксация кадра — временная тестовая инструментализация DOM/браузерного времени, не изменение исходника. После кадра состояния анимаций/видео восстанавливаются. Она не доказывает плавность реальной анимации или идеальное совпадение всех её фаз.
- Стартовый слайд 6 через галерею — шаг 8; последовательный вход — шаг 0. Оба сценария проверяются отдельно.

## Быстрый уровень
Сборка/хеш/открытие, DOM и stage каждого выбранного слайда, повторный вход через другой слайд, gallery open/guard/jump/close. В родителе и обоих iframe декодируются встроенные изображения из img/data-src и CSS url, включая lazy-миниатюры; загрузка всех FontFace. Три видео: decode/play с изменением currentTime и pause при уходе. Ошибки pageerror/console, requestfailed и внешние запросы собираются через browser context. Lazy-миниатюры не считаются сломанными только потому, что ещё не были видимыми.

Это проверка структуры и работоспособности, не визуальная аттестация. Скриншоты можно дополнительно получить `--capture`; отсутствие утверждённого эталона обозначается pending.

## Полный уровень
Всё из быстрого плюс:
- Все 38 соседних переходов вперёд/назад настоящими Enter/Space/ArrowRight и ArrowLeft.
- Bento assemble и очистка, надстройка документов, особый порядок 4/5.
- Timeline 0..8 вперёд/назад, evolution 0..6 и единственная активная сцена, v8 0..10 и возврат/сброс.
- Оба iframe, replay-fighter, start/compose/v8forget/reset, postMessage next/prev.
- Исторический fanout → Solitaire через явное сообщение iframe, наличие клонов и остановка через backFanout. Это сохранённая ветвь протокола, не текущий маршрут __v8Advance.
- Glow typing start/stop, z-index и pointer-events, контрольный кадр свечения; остановка на последнем слайде.
- Исторический `#stage9` в отдельной странице: ошибка фиксируется, не скрывается.
- 77 кадров: 39 settled, 9 timeline, 7 evolution, 11 v8, 9 кадров переходов, Solitaire и glow. Сравнение с ранее визуально просмотренными эталонами.

Тест определяет факт зарегистрированных запросов страницы/iframe; фоновые служебные запросы самого Chrome не являются ресурсами презентации. Внешние ссылки не нажимаются: offline-контракт не запрещает явно открываемые пользователем Konspektus/Telegram.

## Эталоны и сравнение
`regression/runs/<UTC-time>-<mode>/` содержит PNG, diff и report.json. `regression/latest-quick.json` и latest-full.json указывают последний прогон. Дата каталога техническая UTC; в отчёте пользователю используется московское время.

`regression/baselines/manifest.json` фиксирует профиль, версию Chrome, хеш HTML и каждого принятого PNG, а также журнал просмотра. Pixel diff: pixelmatch threshold=0,1, includeAA=false; симметричный поиск соответствия в радиусе 1 пиксель с допуском RGBA 32; допустимая доля оставшихся отличий ≤0,0015 (0,15%). Симметрия предотвращает совпадение удалённого текста только с соседним фоном. Допуск выбран после выявления различий растеризации на неизменном HTML; исходные 74 эталона при этом не переписывались. Контрольные тесты подтверждают обнаружение отсутствующего блока и смещения на 6 пикселей. Изменения на 1 пиксель и очень маленькие области могут пройти этот допуск и требуют ручного просмотра. Этот порог не доказывает отсутствие небольшой локальной ошибки; diff следует просматривать.

Отличия никогда не переписывают baseline. Отсутствие эталона — pending, а не pass. Коды выхода: 0 все обязательные проверки прошли; 1 есть fail; 2 нет fail, но есть pending визуальные проверки. Историческая неисправность stage9 оставляет полный общий прогон с кодом 1; выборочный прогон не запускает чужой исторический сценарий.

Перед принятием кадра требуется визуальный просмотр. Обзорные листы:
```powershell
node scripts/regression/contact-sheets.mjs regression/runs/<run>
```
После просмотра создаётся явный JSON: `run`, `reviewer`, `files` с `name`, `decision: approve|defer`, SHA-256 кандидата и `note`. Затем:
```powershell
npm run regression:approve -- regression/reviews/<review>.json
```
Пример структуры есть в initial-review.json. CLI сверяет хеш просмотренного кандидата; не принимает неуказанные кадры и не заменяет отличающийся baseline без дополнительного `--replace-reviewed`. При явной замене старый PNG сохраняется в baselines/history. Codex не должен использовать этот флаг после обнаружения отличий без отдельного разрешения пользователя. Первичное создание эталонов входит в текущую задачу.

## Найденные проблемы и предлагаемые решения
Исходники не исправлялись.

1. `#stage9` заканчивается на stage=0.95, не 9. Контроллер L113 воспроизводит цепочку advance с задержками 1800 мс, несовместимую с новым маршрутом/блокировкой 4650 мс и внутренними шагами. Предложение отдельного будущего изменения: заменить старые shortcuts на согласованную навигацию через __deckJump и явно определить режим legacy fanout.
2. Слайд 11 (`pdfSlide27`): нижняя практическая заметка и подписи изображения перекрываются presenterBar/выходят ниже безопасной области. Видно на полном PNG. Предложение: отдельно согласовать переразмещение catwin-layout с учётом панели докладчика; проверить каскад 35/37 и соседние сцены. Кадр не принят как правильный эталон.
3. Слайд 12 (`pdfSlide9`): стрелка/ступица спидометра накладывается на подпись «быстрее». Предложение: проверить взаимное расположение ee-speedo-center и ee-speedo-needle, особенно 38-storytelling-layout-corrections.css:69. Кадр отложен.
4. Слайд 31 (`pdfSlide20`): панель Original PDF обрезана правой границей ee-ragui, видна только часть. Предложение: согласовать размещение ee-ui-citation внутри нового размера story-proof; проверить исходное правило 13-rag-reauthed-style.css:128 и поздние overrides. Кадр отложен до подтверждения замысла.

Мем — слайд 9 (`figmaSlide7`), слайд 7 — архитектура RAG. Solitaire сохранился в iframe слайда 10; «stage 9» исторического контроллера и номер слайда 9 — разные понятия.

## Ручная проверка и границы покрытия
Нужны просмотр реальных плавных переходов в нормальном времени, быстрое многократное нажатие/смена направления во время перехода, fullscreen, touch, системная смена видимости окна, и другие браузеры/размеры экрана. Автопроверка z-index не доказывает весь порядок композиции: смотреть glow на реальных переходах и iframe. Screenshot после фиксации времени не измеряет FPS, задержки GPU или непрерывность видео. Зафиксированные визуальные дефекты нельзя объявлять исправленными или автоматически принимать.
